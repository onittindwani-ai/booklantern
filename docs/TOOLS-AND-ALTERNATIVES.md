# Tools and alternatives

Every paid tool Booklantern can work with is scored next to the free or open source option for the same job, so you can choose for your client. The method is in the hub guide `COMPARISON-METHOD` (six criteria, weights 35, 15, 15, 15, 10, 10, one evidence line each, closeness is the alternative's fit divided by the reference tool's fit).

**Read this first.** These scores are judgement from sources and from our own adapter work. They are not benchmarks. A tool marked "not run" was scored from its description only. A source marked "not fetched" was not read at all, and the vendor's own pages are the truth, not this table. No price is quoted here because prices change; read the vendor's price page on the day you decide.

The table below is generated from `data/tool_scores.json` by `python3 tools/score_tools.py`. Do not edit it by hand.

- **When open source is the right call:** Open source is the right call when a client wants their books on their own server or will not pay a subscription and someone can keep the server updated. It is the wrong call when the client's accountant already works inside QuickBooks or Xero.

**Evidence, Gmail over IMAP**

- Cost (80): Works with a normal mailbox. No price checked.
- Data control (40): Mail stays at Google.
- Integration depth (70): Tested against a local mock server for unread, attachments, marking seen after the bills are saved, and leaving mail without a bill unread.
- Sources: https://support.google.com/mail/answer/185833 (checked not fetched, UNVERIFIED)

**Evidence, Any IMAP mail host**

- Fit (75): The same code reads any mailbox that speaks IMAP.
- Setup effort (55): Host name, port and a password. Each host has its own rules.
- Reliability and upkeep (65): Depends on the host.
- Cost (85): Usually included with a domain mailbox.
- Data control (60): Depends on where the host is.
- Integration depth (65): Same tests as the Gmail case, no host specific checks.
- Sources: https://www.rfc-editor.org/rfc/rfc9051 (checked not fetched, UNVERIFIED)

**Recommendation by user type**

- **Beginner:** A dedicated mailbox on Gmail with an app password, because most small businesses have one. Use a mailbox just for bills.
- **Implementer running it for clients:** Create a separate mailbox such as bills at the client's domain and point suppliers at it. The reader only looks at unread mail and marks it read once its bills are saved. Mail with no bill in it stays unread. Set REPLY_TO to another mailbox a person reads.
- **Cost sensitive owner:** Any mail host that offers IMAP works and the reader adds no cost of its own.
- **When open source is the right call:** A self hosted mail server is the right call only if the client already runs one. Do not start one for this.

- **When open source is the right call:** Self hosting on a plain server is right when the client wants the data in their own region or you already run servers. It is not right for a first project with no one to do updates.
