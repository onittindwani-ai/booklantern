# Changelog

## 1.0.2 (2026-11-27)

Documentation and demo label updates.

## 1.0.1 (2026-11-25)

A hardening release: the fixes of a second, stricter self review, in plain words.

- Demo and real installs: the public demo password, the example approver and viewer logins, the demo buttons, the sample demo date and the loading of sample data now work only when `DEMO_MODE=true` and no `OWNER_PASSWORD_HASH` is set. A restart can no longer erase or reload a database that holds data. The example `.env` now says `DEMO_MODE=false`.
- A real install is usable from nothing: vendors (with the bank account on file), customers, open invoices, bank accounts, the chart of accounts and repeating items can be added through new owner only API routes, CSV imports and `tools/load_data.py`. Business name, address, reply address, currency and time zone are settings (`COMPANY_NAME`, `COMPANY_ADDRESS`, `REPLY_TO`, `BASE_CURRENCY`, `DEFAULT_TIMEZONE`); the placeholder company name keeps a live install from starting.
- Reminders carry your name, your postal address, a plain way to stop them and an unsubscribe header. A placeholder payment link is never stored or sent.
- Bill intake: one damaged or hostile attachment no longer loses the other bills in the same mailbox poll (each document is saved on its own, a mail is marked read only after saving, failures are logged without bill text). Mail is read without marking it read, and size and message count limits apply.
- Bill checks: the duplicate and changed bank account checks work with no vendor list, bank details printed as a routing and account pair are read, and a vendor with an account on file whose bill shows none is held back. Amounts of 20 digits, very long text, negative totals and unknown currency codes are limited and flagged instead of breaking a save. Text that looks like markup no longer breaks the month end PDF.
- Safety: mail connections check the server certificate and refuse plain text except to this computer; uploads are read with a size limit as they arrive; the page picture of a huge page is drawn small; the kill switch and force draft set in the app hold for posting, sending and payment links; approve, reject, post and bank links cannot be done twice by two clicks; repeated accounting posts carry a request or idempotency key; spreadsheet cells that start like a formula are written as plain text; a viewer's page never makes a paid model call.
- Sign in: one cleaned email is used for the limit and the lookup, field lengths are limited, and there is a second limit by network address. The web app passes on only the last address of `X-Forwarded-For`.
- Operations: alembic and the worker read the same settings file as the API (`ENV_FILE`), with no silent SQLite fallback; the backup script works from cron, keeps no empty dump and saves the uploads; the data folder is found through `SEED_DIR` first.
- Docs and tooling: `.env.example` and `docs/04-ENVIRONMENT-VARIABLES.md` list every setting, and a test fails when one is missing; the docs no longer say the Docker images were never built (CI builds them and starts the stack, no real host was used); Windows and `python3-venv` notes; `SECURITY.md` points to the private Security tab; the web app has an error page and a not found page.
- Saving before answering: every route now asks for its database session with `Depends(db, scope="function")`, so the save runs before the answer goes out (on FastAPI 0.165 the default scope saved afterwards, and a failed save still read "ok"). Posting a bill saves its claim before the accounting system is asked. A test fails on any route that goes back to the bare form.
- Versions: the API, the root package and the web package are all 1.0.1.

Second independent audit (same release):

- A person can no longer clear the finding their own edit raised. Approving a bill that has, or ever had, a blocking finding is refused for whoever changed the bill or closed one of its findings, and an approver cannot close a blocking finding on a bill they edited. The owner may do both on their own work with a written reason, logged as `self_review`. A closed blocking finding opens again when the same check fires after another edit. The docs now say exactly this (`02`, `04`, `11`, `13`, `14`).
- A bill paid by a matched bank line is marked paid (a part payment lowers what is owed, taking the match away makes it payable again), so payables and the forecast no longer count it twice.
- The same vendor, bill number and amount is a blocking duplicate on any date or with no date; punctuation, case and zero padding in the number are ignored.
- A 1.4 KB PDF can no longer exhaust memory when the live reader lays out its text, and a document whose reading was started three times and never finished goes to a person instead of blocking intake (new column `read_attempts`, migration 0003).
- QuickBooks, Xero and Akaunting drafts carry the tax and the lines of the approved bill; the total the accounting system reports is compared with the approved total and a draft with another total sends the bill back to review instead of counting as posted. These adapters are still tested only against stand ins.
- An edit cannot change a bill that was approved a moment earlier; a network error while posting gives a safe message and an audit row instead of a crash; a reminder is marked as being sent before the mail leaves, so a stop in between never sends it twice; the CSV adapter names a missing column or a bad amount; the backup script fails loudly when the uploads cannot be archived.
- Every change made with the browser cookie alone needs the `x-booklantern: 1` header at the API as well; there is no limit on an account across all addresses (a stranger could keep the owner out); an approver or viewer email equal to the owner's stops the app from starting.
- The review page tells the person when they changed the bill or closed a finding on it (the owner is asked for a written reason, anyone else is told someone else has to approve), a taken back payment never moves a bill into a state nobody approved, and SQLite files made by an earlier version get the new `read_attempts` column added at start.
- Docs: Hetzner env file location, `FORWARDED_ALLOW_IPS` on Railway, how to pin the Docker base images by digest, the header of `constraints.txt`.

Third independent audit (same release):

- Editing the finding away no longer turns off the two person rule. A bill remembers that it ever carried a blocking finding (new column `had_block`, migration 0004, added to older SQLite files at start), so an approver who edits a wrong company, an unread bank account or a duplicate number until the check passes still cannot approve it alone; the owner needs a real reason. A reason must be at least 12 characters in at least 2 words with 5 different letters or digits (one character or `aaaa` is refused), for an approval over a block, for the owner's own work and for closing a blocking finding. A number changed by a character on the same total and vendor within 3 days now blocks like an exact copy.
- A lookalike vendor name hides nothing: a bill with a number is compared with every other bill when either vendor is not on the list, and an unknown vendor that asks to be paid into a bank account blocks. New setting `INTAKE_ALLOWED_SENDERS`: a bill from any other sender is kept but blocked until a person approves it with a reason.
- Bank statements: one strict money reader. The real minus sign, the en dash, brackets and a trailing minus are read as money out, `DR` is out and `CR` is in, and any character it does not know (a second sign, a stray letter) stops the import with every unreadable line listed and nothing imported. A statement must say which bank account it belongs to when there is more than one.
- Mail: a message with no bill in it (a customer's answer, a "stop") stays unread in the mailbox; one from a customer or asking to stop is shown on the Exceptions page. Live mode refuses to start when `REPLY_TO` is empty or is the bills mailbox while one mailbox does both jobs.
- A start with no `DEMO_MODE` line can no longer hold real connections (QuickBooks, SMTP and so on) or `ACCOUNTING_WRITE=true` in live mode while the public demo password is active, unless `ALLOW_DEMO_SERVER=true`. The API image now starts with `DEMO_MODE=false`.
- Matching: an invoice or bill that is still open always wins over one already marked paid, a part paid imported invoice offers only what is still owed and ends paid when the deposit arrives, a line that fits only a document already marked paid is confirmed by itself only when it names that document's number (otherwise it is suggested), linking a line to an invoice that was already paid changes nothing about it, and an invoice paid by a matched line gets that line's date as `paid_on`. A deposit marked as a part payment that is exactly half, a third or a quarter of an invoice goes to the invoice it divides. Imported paid invoices no longer get their issue date as the date they were paid (a `paid_on` column can be given).
- Sending: when the connection fails after the mail was handed to the server, the reminder stays "sending", a person is told to look, and it is never sent again by itself; a failure while saying goodbye after the server took the mail counts as sent; a refused address is one try, and any other failure is tried five times at most.
- Posting: for an accounting system that cannot recognise a repeated request (Akaunting, the CSV adapter) an unclear outcome keeps the bill in `posting` with a blocking finding until a person says whether the draft is there (new route `POST /api/bills/{id}/post-outcome`, a panel on the review page). "Never a second one" is now said only for QuickBooks and Xero, which carry the key.
- Smaller things: the approval carries a fingerprint of the bill (`etag`) and is refused when the bill changed after the page loaded it; changing a vendor's account, purchase order rule or tax rate checks its waiting and approved bills again and sends an approved bill that now blocks back to review; the web app sends a Content-Security-Policy header; `data/counts.json` is checked against the code by `tools/check_docs.py`.

Fourth independent audit (same release):

- Amounts in a currency with three decimals (KWD, BHD, OMR, JOD, TND) are read right: `12.345` and `12,345` are twelve and a bit, no longer twelve thousand, in bank statements, the invoice import and the bill reader. An amount that could be thousands or decimals and has no currency at all is refused and its line listed. A sign that does not fit the currency (a euro sign on a dollar account) refuses the amount, and an invoice total written with its own currency (`EUR 1,250.00`) is read in that currency.
- Bank statements: the same line in a second account is imported and counted (the check for a repeated import is per account; lines saved by the earlier version are recognised and re-keyed). Lines dated before an account's opening date are kept but not counted in the balance, and the import says how many; this stops a statement of old history from counting the same cash twice in the balance and the forecast.
- Mail: a signature or logo picture inside a message (Outlook's `multipart/related`) is no longer taken as a bill, so the message stays unread and a "stop" in it is shown. A second "stop" or a new answer from a customer opens the finding again after the first was closed. A file called a PDF or picture that is neither is listed as "File not read" instead of vanishing.
- A bill whose total is written in a currency this system does not know (TWD, COP, NT$) is held with a blocking "Currency not known" finding that says its amounts are a placeholder in the company currency, not amounts in that currency (before, nothing said so).
- Matching: a deposit that names an invoice already marked paid is only suggested when another invoice of the same amount is open, and paid invoices no longer take part in a split. A hand link counts what an imported invoice already holds as paid.
- A bill left in "posting" by a stopped program is found after 15 minutes and gets the "Posting outcome unclear" finding; that finding cannot be closed by the general close route while the bill is posting, only by saying what happened on the bill.
- Smaller: only the owner can set an exchange rate; a bill edit logs the old and new value of each field; the CSV accounting adapter reads amounts in the company currency.
- Tests: the money tests that depended on the day and hour (they passed only Monday to Friday between 9 and 17 in New York) now run on a pinned clock, and `BOOKLANTERN_TEST_NOW=<time>` runs the whole suite as if it were that moment (checked on a Sunday at 03:00 New York time).
- Docs: the opening date, per account statements and decimals (`05`), the `ALLOW_DEMO_SERVER` row (`04`), the interactive `/docs` page (off in a real install), and new honest notes and known gaps (`14`).
